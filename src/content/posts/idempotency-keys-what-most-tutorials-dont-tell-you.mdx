Payment App တစ်ခုကနေ ငွေ 50,000 လောက်ပိုက်ဆံလွဲမယ်ဆိုပါစို့ App ထဲမှာ Pay ကိုနှိပ်လိုက်မယ် လိုင်းအခြေအနေကြောင့် Loading.. ဖြစ်နေမယ်။ နည်းနည်းကြာလာတာနဲ့ Request Timeout ဆိုပြီး Alert Dialog လေးနဲ့ပေါ်လာလိမ့်မယ်

အဲ့လိုအခြေအနေကြရင်မေးစရာတစ်ခုရှိလာတာက 

> ငွေက တကယ်ရော ထွက်သွားပြီလား?

အဲ့လိုအခြေအနေမျိုးမှာ Pay ကိုနောက်တစ်ကြိမ်နှိပ်ကြတဲ့ အခါ

request ကတော့နှစ်ခါထွက်သွားလိမ့်မယ် Backend ဘက်မှာတော့ အရင် Idempotency မသုံးထားခဲ့ရင်တော့ Request ကိုနှစ်ခါ Process လုပ်ပြီး 100,000 လောက်ဖြတ်သွားပါလိမ့်မယ်

## ပထမဆုံး Idempotency ဆိုတာဘာလဲ?

> You can send the same request multiple times, but it will be processed only once.
> Requests တွေကိုအများကြီးပို့လို့ရပေမဲ့ တစ်ခါပဲ process မယ်

Same logical operation ကို same idempotency key နဲ့ ဘယ်နှခါ retry လုပ်လုပ် side effect ကို တစ်ကြိမ်ပဲ ဖြစ်စေမှာပါ

ဥပမာ —

```http
DELETE /users/123
```

တစ်ခါ delete လုပ်တယ်။
နောက်တစ်ခါ ထပ် delete လုပ်တယ်။

User က မရှိတော့ဘူး။
System state ကလည်း အရင်အတိုင်းပဲ။
ဒါကို idempotent လို့ပြောတယ်။

ဒါပေမယ့် —

```http
POST /payments
```

ကတော့ ကွာတယ်

Request နှစ်ခါရောက်လာရင် payment နှစ်ခုဖြစ်သွားနိုင်တယ်။

အဲ့ဒါက တော့ idempotency key ကိုမသုံးထားရင်ဖြစ်တတ်တဲ့ ပြဿနာ တစ်ခုပါ

ဉပမာ Payment App တစ်ခုမှာ Idempotency ကိုသုံးတော့မယ်ဆိုရင် Key ကို Payment Request တိုင်းမှာ ထပ်ခါထပ်ခါ Generate လုပ်ရမှာမဟုတ်ပါဘူး

```javascript
// ဒီလိုမျိုး Process Click တိုင်း ပို့နေမယ်ဆိုရင်တော့ idempotency key 
// ကိုသုံးတာဟာ အဓိပ္ပာယ်ရှိတော့မှာမဟုတ်ပါဘူး
async function sendPayment() {
    const key = crypto.randomUUID();

    await fetch("http://localhost:3000/payments", {
        method: "POST",
        headers: {
            "Content-Type": "application/json",
            "Idempotency-Key": key
        },
        body: JSON.stringify({
            amount: 50_000,
            currency: "MMK"
        })
    });
}
```

ဒီ code ရဲ့ problem က sendPayment() ခေါ်တဲ့ အကြိမ်တိုင်း key အသစ်ထုတ်နေတာပါ

```text
First click
key = aaa

Retry
key = bbb

Retry
key = ccc
```

Backend အမြင်မှာတော့ ဒီသုံးခုက operation အသစ်သုံးခု ဖြစ်နေမယ်။ ဒါကြောင့် idempotency က duplicate ကို မတားနိုင်တော့ဘူး

ပိုမှန်တဲ့ design က payment operation စတဲ့အချိန် key တစ်ခုပဲ generate လုပ်ပြီး retry တွေအားလုံးမှာ ပြန်သုံးတာပါ:

```javascript
const paymentKey = crypto.randomUUID();

async function sendPayment() {
    await fetch("http://localhost:3000/payments", {
        method: "POST",
        headers: {
            "Content-Type": "application/json",
            "Idempotency-Key": paymentKey
        },
        body: JSON.stringify({
            amount: 50_000,
            currency: "MMK"
        })
    });
}
```

## TL;DR

Client ကတော့ same key နဲ့ request တွေပို့လိမ့်မယ် process ထားတဲ့ results တိုင်းကိုတော့ store ရပါလိမ့်မယ် ပြီးရင် အဲ့ result ကို retry လုပ်တဲ့အခါတိုင်းမှာ return ပြန်ရပါလိမ့်မယ် ကိုယ့်ရဲ့ App ဟာ ဘယ်လောက်ပဲ မြန်မြန်နဲ့ failure recovery တွေရှိနေပါစေ client ဘက်က double tap ကိုတော့ process လုပ်ဖို့အဆင်သင့်ဖြစ်သင့်တယ်လို့ထင်ပါတယ်
